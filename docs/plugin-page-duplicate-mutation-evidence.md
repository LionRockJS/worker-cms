# Durable contributor page duplication — 4 November 2026

This continues W4b/R3 after the [single/batch creation slice](plugin-page-create-mutation-evidence.md) on `883df7c`, integrated with the independent W12 lifecycle work on `50aa0b4`. `POST /__cms/pages/duplicate` now has a guarded operation intent, exact source-to-clone receipts and a durable manifest for every committed chunk. Each chunk commits its copies, initial history, inherited protection and receipts in one private-D1 transaction. This completes this duplication-evidence family, not W4b or general recovery.

## Credential and source authority

The route captures a duplication-specific shared page-mutation proof before parsing its body. Stable registry ID/UUID, enabled URL binding, dedicated stored/resolved/inbound secret, exact identity pin, current declared concrete/wildcard write grants, classification generation and the registry-receipt witness remain guarded. A read grant alone cannot authorize a clone. A removed/reclaimed same-second pin cannot revive an old request. Creation and update proofs cannot authorize this producer.

The actor is `plugin:<registry UUID>` with null CMS user, roles and session. Acting-user headers remain explicitly unverified assertions and legacy payer selectors. Covered source/count reads and separate hook delivery use this credential principal. Forbidden page-type decisions require a classified `page.duplicate.denied` receipt before a normal 403; syntactic selector/ID/cursor failures do not invent successful mutations.

The request reads a bounded, ordered snapshot of at most **1,001 source pages**: 1,000 possible copies and one look-ahead. It also captures their exact tag-link metadata, tag identities/taxonomies and retained UUID floors. Complete selected page fields, bounded membership, total matching count and classification metadata are checked before intent and every chunk, including after the writes. A changed/deleted/reparented source, new selected member, changed source association/taxonomy/floor or changed current authority refuses the next affected phase. Sources already copied remain part of the frozen request snapshot, so a later chunk cannot silently adopt an updated version of an earlier source.

Protected complete-source and relationship metadata reads are awaited before transforming or reserving. The existing private `page.duplicate-count` estimate remains audited. Each chunk additionally persists the existing `page.duplicate-read` checkpoint for its selected sources and look-ahead, with operation/chunk/cursor metadata. A later read-evidence outage stops further chunks without replaying the committed prefix. Source/count audits exclude raw selector values, content, names and credentials; selector/transform fingerprints identify observations without retaining the incoming free-text transform.

## Frozen sources and cursor behavior

Each request freezes its original selection before allocating targets. Source guards exclude **that operation's own planned clone UUIDs** from its collection query/count. A clone that inherits the same pointer or parent therefore cannot recursively become another source during the same request. Original rows and source associations remain untouched.

The valid request/response contract remains: pointer or parent selection, blueprint defaults followed by source lect, requested dropped keys, overrides and draft metadata; source name/weight/date/timezone; explicit target parent; and `{ count, next_cursor, done }`. Slugs retain the source slug family, including pseudonymous source slugs, with the existing fallback and collision allocation. Existing physical source tag links are not copied. Source protection is inherited separately.

At most 1,000 originals are copied per call, in chunks of at most 100. `next_cursor` remains the last original source ID, not a generated clone ID. A 1,001-source continuation test copies 1,000, returns the original cursor with `done:false`, then copies the remaining original into the separate target collection. Source IDs/cursors must be safe integers and new target parents must exist. The frozen look-ahead is audited even when it is not copied in this call.

A numeric cursor is not an operation/retry token or a persisted collection cutoff. A **new** request takes a new source snapshot. If earlier outputs still match its selector, they can be eligible sources in that new request; callers need an appropriate transformed target selection or a separately controlled cutoff. Durable continuation identity and automatic retry/lookup remain R5. This slice does not claim cross-request deduplication.

## Shared creation transaction and inherited protection

The audited creation writer now accepts a trusted duplication adapter: frozen source checks, per-target source ID/UUID/protection and private operation metadata. It supports the bounded 1,000-target preparation while each actual write transaction remains capped at 100. ID reservation checks use JSON-array bindings so the larger request does not require one lookup per fifty IDs. The shared writer detects actual trash-table presence, reserves retained trash IDs when present and guards that schema-presence decision. A deployment without the optional trash tables can still duplicate; enabling or removing them during preparation refuses the stale operation. The last production caller of the unaudited bulk-insert primitive is removed, along with that primitive and its obsolete timestamp helper.

A single guarded `page.duplicate.intent` precedes the existing upfront optional reservation for the complete bounded set. Total/per-parent/per-pointer admission uses the **actual transformed candidate set**, including inherited pointers that the old override-only precheck missed. Existing creation safeguards recheck current quota/pricing catalogue, settings, IDs/UUID absence, target parent, slug availability, safe numeric allocation and policy. Each chunk checks its own admission count against current usage; later quota/authority changes may refuse after a previously committed prefix. Configured unlimited limits and scoped exemptions remain.

Every copied page gets a `page.duplicate` success receipt targeted at its new stable UUID. Detail includes the shared operation, registry/identity correlation, source ID/UUID, enforced copied protection level, new history UUID and operation-level reported reservation amount. It excludes source bodies, names, slugs, raw pointers, dropped-key/override values, URLs and credentials. New histories exactly match the copied lect and retain the established `create` history action. Protected sources cannot lose their classification merely because their association or fields are omitted from the clone: captured content/type/table/taxonomy/UUID protection is pinned on the new UUID in the same transaction. The source's own floor/body is not rewritten.

Every chunk also commits an exact `page.duplicate.chunk` manifest with chunk index, source/target identity pairs, count, original cursor before/after, request completion and `done`. Final page/history/floor/parent/slug/quota/source assertions and rechecks of **all** new receipts reject ignored, deleted or rewritten state/evidence, including later history/chunk triggers that corrupt an earlier page receipt. A failed chunk rolls back as one unit; it does not roll back earlier committed chunks.

Aggregate floor provenance excludes this operation's own new UUIDs. Pinning a table-classified source onto its clones therefore does not manufacture a stale source-floor conflict on the next chunk, while other concurrent provenance changes remain guarded. Exact final clone-floor checks still apply. Fingerprints are reconciliation identifiers, not an anonymization guarantee.

## Prefixes, reservations and uncertain outcomes

The existing upfront reservation charges the planned bounded copy count. Its internal operation ID correlates the intent, all chunk/page receipts and the existing tagged debit/caller-refund notes; host ledger display retains its prior presentation. No financial feature implementation is imported across the optional-feature boundary.

Progress advances only after an acknowledged local chunk commit. A known rollback or failure before the next chunk was attempted permits **one proportional refund attempt for the uncommitted remainder**. Confirmed prefix pages are never replayed or refunded. A transport/lost-acknowledgment error after a chunk was attempted can follow a complete chunk/receipt commit; compensation for the unacknowledged remainder is withheld, including unstarted later work, pending reconciliation. An uncertain upfront debit starts no copy chunk and is not blindly refunded.

`page.duplicate.result` error evidence attempts to record `not_committed`, `prefix_committed`, `committed` or `unknown` operation state, the unacknowledged portion's state, last acknowledged count/cursor, chunk index and fixed refund state. It does not call a committed prefix a full rollback. The legacy callback's normal return proves only **refund attempted**; financial completion remains unconfirmed until independently reconciled. Error-result evidence may itself be unavailable after grant/policy/audit changes, in which case coarse incomplete health evidence is attempted. Durable intent and committed page/chunk receipts remain available for controlled reconciliation.

A later new request can duplicate logical content and charge again. This producer introduces no automatic content/reservation/refund replay, durable client idempotency token, compensation retry or lookup service. Financial writer completion and general multi-step recovery remain R3/R5.

Post-commit `create` hooks retain their existing event semantics under the credential principal. They suppress the former duplicate best-effort `page.create` audit entry; duplication success is now represented by `page.duplicate` and its chunk manifests. Hook failure does not undo local copies. Intent/delivery/retry for external effects remains R4/R5.

## Bounds and remaining scope

Complete source snapshots, metadata catalogues and selected plans retain the shared **5,000-row / 1,000,000-byte UTF-8 JSON** bounds per snapshot/manifest. The source reader separately limits its body set to 1,001. Large legacy rows or a request whose complete bounded set exceeds the budget refuse before reservation; the old per-chunk body streaming does not establish capacity acceptance for this stronger whole-request snapshot. Missing source/history/association/security/audit schema, malformed policy, unsafe IDs and tested state/receipt rewrites fail closed with 503/no-store. Deployment subrequest/latency/concurrency capacity and retention remain R6 acceptance work.

W12's independently committed controls remain intact: this path does not delete or overwrite original sources, and a source removed before a guarded chunk cannot be copied by that old request. Recorded source-to-clone lineage supports later governed recovery/erasure review; it does not automatically propagate holds or erasure to new UUIDs or supply approved processing purposes/retention periods. Those owner and global lifecycle obligations remain open.

Four W4b packages R3–R6 remain, provisionally **18–32 engineering person-days** plus external acceptance; see the [scope register](w4b-remaining-scope-2026-11-02.md). Contributor deletion/children evidence is next, followed by tag provisioning and the remaining ingestion/service/financial/job writers, external effects and recovery/acceptance. Regulated business writes remain blocked. This increment adds no schema migration and performs no production mutation, push, deployment or compliance sign-off. W12's existing migration/runbook requirements remain its own scope.
