# Durable contributor single/batch page creation — 4 November 2026

This continues W4b/R3 after the [contributor page-update slice](plugin-page-update-mutation-evidence.md) on `11b3777`. `POST /__cms/pages` and `POST /__cms/pages/batch` now commit their accepted local pages, initial history snapshots, tag associations and exact classified `page.create` receipts in one private-D1 transaction. A guarded durable intent precedes the existing optional credit reservation. This completes this creation family, not all contributor writers or the financial/recovery packages.

## Authority and guarded preparation

Creation captures the shared page-mutation authority before body parsing, with a creation-specific proof and source-read action. It checks the stable registry ID/UUID, enabled URL binding, dedicated stored/resolved/inbound credential, identity pin, current exact declared concrete/wildcard write approvals and classification generation. Blueprint declarations require explicit current ownership grants. Read-only and undeclared grants do not authorize creation. The registry-receipt witness introduced by the update slice prevents an old request from adopting a same-second pin reclaim during subsequent configuration resolution. Update proofs cannot be used as create proofs.

The actor is `plugin:<registry UUID>` with null CMS user, roles and session. Safe acting-user IDs are explicitly unverified assertions; malformed/unsafe assertions are marked without their raw value. The existing header-based payer selector remains a legacy billing contract, not verified CMS-user/session authority. Covered subsequent reads and separate hook delivery use the credential principal.

Existing per-item validation, explicit/generated IDs, draft/trash ID reservations, slug allocation, parent-chain filtering, partial valid batches and indexed error responses remain. A batch can create a parent and its forward-referenced children. Selected existing external parents must retain their ID/UUID/type and sensitivity metadata; this establishes relationship existence rather than permission to edit their bodies. Tags must resolve before reservation, unsafe/nonpositive tag IDs receive indexed validation errors and duplicate tag IDs are normalized. Missing associations cannot silently become orphan links. The older search fixture now seeds a real tag rather than relying on orphan provisioning.

Preparation takes bounded snapshots of the contributor registry/pin/grant catalogue and local limit/price setting rows. It records the latest global registry receipt to detect supported lifecycle replacement even when timestamped fields are identical. These snapshots bind the existing effective quota/pricing resolver to the captured database inputs; unrelated catalogue changes may conservatively refuse the request. Effective blueprint/default-language configuration and remote-manifest discovery retain their established caches. Fresh schema/remote-manifest reapproval on every partial request is not introduced.

Selected planned IDs/UUIDs, history/link absence, new UUID-floor absence, external parents, tag identity/taxonomy, slug uniqueness and classification are checked before intent and again for the page transaction. Full content/association plans retain the shared UTF-8 manifest bound. Protected authority, catalogue, parent, quota/count and configuration reads are awaited before reservation; strict pending reads flush. The new evidence excludes names, slugs, bodies, raw pointer values, labels, URLs, credentials and configuration values.

## Quota decisions at the transaction boundary

The current total, per-parent and per-pointer definitions/configuration are resolved through the existing plugin limit model. Admission predicates run inside the final serialized page batch: the current count plus the complete accepted set must fit each applicable limit. Final counts must remain within the same limits. Ordinary callers can consume available headroom without a stale Worker-side count CAS at the page-write boundary. Concurrent last-slot requests cannot exceed a cap through these converted routes. A raced admission can return 503; a later request observes the current quota. Legacy count-then-insert writers and trash restoration retain their own contracts and can still change the overall count outside this producer.

Numeric/text forms of an equal pointer are counted consistently using text-normalized SQLite extraction, matching candidate grouping. Missing parent/pointer groups retain their existing exemptions, and configured unlimited values remain unlimited. Counts and configured limits must be safe integers. Aggregate UUID-floor provenance for the inspected page types is checked at admission and against the expected result so a newly protected count source cannot silently be adopted under stale classification.

An observed quota refusal requires a guarded classified `page.create.denied` receipt with fixed `limit_exceeded`, current/attempted/maximum numbers and operation correlation before returning the existing 409 body. It does not reserve credits or create pages. Forbidden page-type attempts require classified denied receipts with type fingerprints, before a normal single 403 or indexed batch refusal. Validation/ID/parent errors do not invent successful mutations. These preflight decisions are their own durable phase and may remain when a later reservation or page phase fails.

## Intent, content receipts and separate financial effects

A successful preflight commits `page.create.intent`, targeted at an internal creation-operation UUID, with the accepted internal page-ID/UUID manifest and `phase:intent`. It is evidence of preparation, not proof of created content or delivered external effects. Exact receipt and source checks surround this phase. Its acknowledgment must succeed before the reservation service is called. A lost intent acknowledgment may leave that intent committed, but starts no charge or content batch and is never automatically replayed.

The optional reservation still runs through the neutral feature-service dispatcher. Its input now carries the creation operation ID. The credits provider records that ID in tagged debit/caller-refund note envelopes, while preserving prices, currencies, shared-pool fallback, charging actions and free/no-payer behavior. The host ledger display preserves the former batch breakdown/empty-note presentation and keeps the correlation envelope in stored evidence; unrelated notes retain their existing display. Other providers and internal multi-currency compensation retain their existing contracts. A service-reported refusal requires `page.create.denied` with `reservation_refused` before the stable 400/402 response; it does not pretend to establish a new transaction-bound financial eligibility decision.

After an acknowledged reservation, one D1 batch inserts all accepted pages, initial histories, tags and per-page `page.create` success receipts. Planned page UUIDs and new history/link UUIDs support exact reconciliation. Numeric history/link IDs are allocated above the stored maximum within the batch and checked for positive safe-integer values. Final checks verify complete selected page fields, creation/update bounds, exact history bodies/actions/timestamps, association sets/metadata, parent existence, slug uniqueness, derived UUID floors, quotas and current authority/configuration/classification. Receipts are rechecked at completion so a later page/history trigger cannot corrupt an earlier item's event. Any tested ignored/aborted/removed/rewritten business or receipt statement rolls back the whole local accepted set.

Success receipts use stable page UUID targets and `content_mutation` retention. They retain operation/registry/identity correlation, fixed principal/field metadata, version UUID, internal tag IDs and the operation-level reservation amount reported by the service. All pages in a batch refer to that same operation-level amount; it is not a separate per-page debit. Classification conservatively includes inspected authority/configuration/contributor/count sources, content containers, selected taxonomies and parent/UUID provenance. Newly protected associations raise the new page's UUID floor in the same transaction.

## Failure, uncertainty and recovery limits

A known SQLite batch rollback, or failure before a page batch was attempted, permits one caller refund attempt for its acknowledged reservation. A transport/lost-acknowledgment or uncertain result after the page batch was attempted does **not** trigger a refund: complete pages and their success receipts may already have committed. A lost reservation acknowledgment similarly does not start a page batch or blindly compensate an unknown debit.

`page.create.result` error evidence attempts to record the operation's `not_committed`/`unknown` content state and fixed refund state. The legacy refund callback deliberately swallows some failures and returns no durable completion status. A normally returning callback is therefore recorded only as **attempted**, never as confirmed financial recovery. A thrown refund is unconfirmed; an unknown content commit withholds compensation. Failure-result evidence may itself be unavailable if authority/classification or audit storage changes; coarse incomplete health evidence is attempted. The durable intent, success receipts when present and correlated ledger notes remain reconciliation inputs.

There is no automatic content/reservation/refund replay and no client idempotency token. A later new request can duplicate logical content unless its explicit-ID contract refuses it. Explicit IDs do not deduplicate a reservation whose page phase never started. Operation lookup, financial completion verification, controlled retries and cross-step reconciliation remain R3/R5. This is not an atomic wallet/page transaction and does not complete financial writer evidence.

Post-commit hooks suppress duplicate best-effort mutation events and their former name/slug detail. Hook delivery remains a separate best-effort effect under the verified credential actor. Result-response auditing is also a separate boundary: a protected response may be withheld after a fully evidenced local creation, without undoing or refunding that commit. External delivery/retry remains R4/R5.
