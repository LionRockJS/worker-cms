# Sensitive-read and outbound coverage review — 31 October 2026

Reviewed the local working tree on HEAD `2e49890`, including the previous P0 increments and changes through the fifteenth increment. This is a repository source review with local regression evidence. It does not verify production bindings, external plugin implementations, public storage domains or recipients' existing copies.

## Count and scope

**Five P0 work packages remain open: W0, W1, W2, W3 and W4a.** These are acceptance packages, not five absent safeguards or five ISO controls. COV-01–08 were implemented in the eighth increment; the ninth/tenth implement host source coverage and identifier retention for COV-09/12; the eleventh implements retained-sensitivity containment for COV-10. The twelfth/thirteenth implement COV-11 metadata/count/source snapshots. The fourteenth implements COV-13, enforcing the W4b write prerequisite at known business entry points. **All listed host changes in COV-01–13 are implemented locally; this does not close deployment/owner acceptance.** Queue-consumer preparation, reviewed plugin pins, historical recovery, governed declassification/retirement, external manifests and deployment/owner evidence remain explicit dependencies.

W4b remains P1 **and a prerequisite for enabling regulated writes**. The regulated profile now holds host business/configuration writes, queue execution, ingestion and recurring billing before their known entry-point side effects. Designated session lifecycle, withdrawal/revocation and audit maintenance retain existing guards. Ordinary deployments keep existing mutation behavior: a later audit refusal does not undo a committed mutation. W5 monitoring support exists locally; actual receiver escalation, outage exercises and protected archival are not demonstrated by these tests.

Method: enumerated the core/admin and optional-feature routers; traced shared rendering, database-return projections, plugin dispatch, publication/withdrawal, queue/cron, Durable Object, file/cache and audit-reader boundaries. Rechecked `fetch`, service-binding fetches, R2 writes, `PUBLISHED_DB` and WebSocket call sites against the existing helpers. Browser asset calls were traced to their server endpoints. Authentication, static-resource and internal coordination traffic are distinguished from content disclosures below. No production data was queried.

The new read events contain identifiers/counts/classification and fingerprints, not content, credentials, identity values, ledger notes or raw search criteria. Ordinary unclassified containers still produce no classified read event. A known PHI audit source cannot become public merely because its table has no policy or a lower policy; policy/inventory availability checks still apply.

`table:credit_wallets` uses `user_id:currency`, `table:shared_credits` uses the currency, and `table:plugin_sequences` uses `plugin_id:key`. These identify logical default/zero states as well as existing rows. Metadata keys use settings keys, locale codes, `locale:message_key`, role names and unique approval composites. `role_permission_set` and `role_state` targets include effective built-in/default states; configuration default setting keys are logical sources even if no stored override exists. Other row targets use actual IDs. Contributor-supplied acting-user headers remain assertions by the authenticated contributor; they are not independent end-user authentication.

## Repository coverage disposition

Groups are bounded by shared implementation, rather than counted once per route or standard. Local implementation does not authorize activation of an incomplete regulated profile.

| ID | Local source status | Remaining acceptance | Plan |

Reopen the ledger for newly identified consumers or fields | W0/W1/W4a |
| COV-13 | Known host business/configuration entry points are contained while W4b is unfinished | Prepare producers/consumers, queued-job recovery and reviewed pins before activation. W4b evidence is required before lifting containment; external plugin GET behavior still needs its owner | W0/W1/W4b |

All announced classified identifier sets now retain every supplied ID in rows of at most 100 IDs. Large sets share `detail.manifest_id`, numbered parts, total part/ID/target counts and an explicit completeness flag. Combine those parts to investigate the whole set; retain the existing actor, classification, query fingerprint and destination/operation detail. Source-only HTTP comparisons preserve session/source-IP context; off-request reads use the explicit actor or an honest autonomous identity.

The manifest is metadata in the existing private audit stream, not a second storage system or proof of independent tamper resistance. Ordinary PII reads retain their existing best-effort persistence policy; PHI reads, outbound exports and inline clone source reads are awaited. An incomplete ordinary read announcement is explicitly marked; an incomplete floored record read or classified record export is refused. Aggregate query counts are not falsely represented as record-ID lists. Protection/retention/archival and external recipient record manifests remain evidence requirements.

Clone evidence is **intent to process actual selected sources**, including one look-ahead row. A later chunk's audit failure can leave earlier clones committed; the handler stops and never automatically replays or claims rollback. Clones now copy retained sensitivity in the business batch, and incoming published copies inherit the actual audited source. Idempotent recovery and atomic mutation receipts remain W4b. Do not enable regulated writes merely because source reads/classification are protected.

Legacy R2 objects without complete taxonomy provenance may now be refused when taxonomy policies apply, and the regulated profile requires both type and taxonomy provenance. Contain/remove regulated historical copies. Rebuild metadata only from verified approved non-PHI sources; do not infer it from current draft associations or bypass the PHI publication block.

Retained floors backfill only classifications/associations still observable at upgrade. They cannot reconstruct erased pre-installation history. Review backups, quarantine unknown copies and use reviewed additive backfill where evidence exists. Direct public R2/CDN/published consumers need their own containment. No production upgrade or existing-object cleanup occurred. See the [runbook](sensitivity-floors.md) for core-first/trash upgrade ordering, traffic containment, effective inventory and rollback limits. The guarded transition policy intentionally refuses declassification until a reviewed workflow exists; W4b/W5 still govern durable transition evidence and approved retirement.
