# Durable contributor page updates — 3 November 2026

This continues W4b/R3 after the [sequence-counter slice](plugin-sequence-mutation-evidence.md). Single-page `PUT /__cms/pages/:id` and `PATCH /__cms/pages/:id`, plus `PATCH /__cms/pages/batch`, now commit accepted local page changes, their new history snapshots, submitted single-page tag replacements and exact classified `page.update` receipts together in private D1. This completes this update family, not all contributor page writers or W4b.

## Current contributor authority

`page-update-evidence.ts` captures authority immediately after dedicated-credential authentication and before body parsing. It verifies the stable registry ID/UUID, enabled registration, URL binding, stored/resolved/inbound dedicated secret and exact identity pin. The requested manifest remains subject to discovery's existing TTL. Blueprint declarations are requests: an explicit current write approval is required for each owned schema. Delegated concrete/wildcard write types must be both declared and explicitly approved. Read grants and undeclared grants cannot authorize writes.

The full current approval catalogue is captured and checked, alongside the registry, pin and classification generation, at transaction admission and completion. The request also captures the latest primary registry-receipt sequence for its stable registry UUID. A supported lifecycle writer can remove/re-create an identical pin or grant within the same clock second; its new receipt still changes this witness. In particular, a host automatic claim during later configuration resolution cannot revive an old request whose pin was removed while its body was being read. A claim's independently committed host receipt may remain even though this page update refuses. Read-only assertions and page receipts do not advance that registry witness. Concurrent archive removal of its witnessed receipt can conservatively refuse an in-flight operation; this is not a permanent requirement to retain every old claim in the hot stream.

This witness complements the physical state snapshots. It does not infer unrecorded direct-SQL lifecycle history or establish a new remote-manifest authenticity guarantee. Global writer/operator reconciliation remains R6.

The principal is `plugin:<registry UUID>`, with null CMS user, roles and session. A safe positive acting-user header is retained only as `asserted_user_id` and `acting_user_verified:false`; unsafe assertions are marked without the raw value. Covered subsequent source/configuration/result reads and separate hook delivery use the credential principal. No HTTP user or CMS session is fabricated to reuse the administrator editor service.

## One local transaction

The shared bounded SQL helper captures the selected complete draft rows, exact tag-link metadata, existing history catalogue (IDs, UUIDs, page membership, timestamps and action), relevant tag identity/taxonomy metadata and UUID sensitivity floors. A point writer does not load unrelated pages or historical lect bodies. Guards close stale source, membership, history-catalogue, taxonomy, pin/grant, credential and classification changes.

Single-page partial merge, metadata changes, custom history action, existing `if_lect` comparison and successful response shapes remain. Submitted valid tag arrays replace memberships in the same transaction; duplicate IDs are normalized. Nonpositive/unsafe association or parent IDs receive 400, and missing new tag/parent targets refuse before any local change. An unchanged pre-existing orphan parent remains tolerated. A changed slug is checked for collision inside the batch; a changed parent must still exist at completion. Neither parent existence nor tag association grants authority to edit another page's body.

Batch PATCH retains its lect-only contract, 100-item limit, indexed validation/missing/duplicate/forbidden errors and omission of per-page live-editor notifications. All accepted items and named policy refusals share one operation ID and one local transaction. A failure on a later item, snapshot or receipt rolls back the entire accepted set and its receipts. Input-validation errors and absent targets do not create fictitious mutation receipts. The complete client retry/error manifest remains a broader R5/R6 contract.

Each accepted item receives a distinct history UUID. Numeric history IDs are allocated above the stored maximum inside the serialized transaction, using the shared core allocator, and checked for positive safe-integer values. Replaced tag links receive planned UUIDs and transaction-allocated safe IDs. Exact final page fields, preserved creation metadata, transaction-time updates, complete selected link set/metadata, preserved old catalogue identities and exact new history bodies/actions/timestamps are checked. A later page/version trigger cannot silently corrupt an earlier batch receipt: every receipt is checked again at completion. The old bulk-update primitive is removed; these routes no longer separately call the raw history/tag writers.

The history-catalogue invariant does not claim a byte-for-byte snapshot of all old historical bodies. Production SQL appends history and does not update those bodies. Arbitrary direct operators, unrelated pages and other unmigrated writers still need their own evidence contracts.

## Classified private success and refusal evidence

The highest effective classification of the inspected authority/journal/content tables, contributor scope, page type, current/selected tag taxonomies and retained UUID floor applies. New classified associations raise the floor in the same transaction; removing an association cannot reduce a retained floor. Final floor checks require the exact expected retained/derived level. The same classification generation is checked through completion.

Protected page, authority, journal and relationship/history metadata reads are awaited before writing; strict pending reads are flushed. Internal IDs and UUIDs describe the selected sources. The new receipts target stable page UUIDs, use `content_mutation` retention and retain only operation/registry/identity correlation, fixed principal metadata, changed field names, new version UUID and internal association manifests when tags are replaced. Names, slugs, content bodies, expected lect, raw credentials/configuration, remote URLs and free-text version-action labels are excluded. Existing effective blueprint/default-language configuration and discovery caches retain their established TTL behavior; this slice does not claim fresh remote/local schema reapproval on every partial merge.

Forbidden page-type decisions require exact classified denied `page.update` receipts before a single 403 or mixed-batch indexed refusal is returned. An observed stale `if_lect` requires a denied receipt with fixed `version_precondition` before the existing 409 response. Primary refusal-evidence failure returns 503; no CMS-user denial outbox is falsely used for a plugin service principal. If the captured target changes before the transaction, the guarded operation is unavailable rather than adopting the newer body as its source.

Post-commit hooks suppress the duplicate legacy best-effort `page.update` event and its name/slug detail. Hook delivery and the single-page live-editor saved notification remain separate best-effort effects; their failure cannot undo a local commit. External intents, exact delivery/retry and recovery remain R4/R5. Protected result-response auditing also remains a separate response boundary: a post-commit response failure does not imply rollback of an already evidenced local mutation.

## Bounds, uncertainty and remaining work

Selected snapshots retain the shared 5,000-row and 1,000,000-byte UTF-8 JSON bounds per source/manifest. Large histories or content/association manifests require reviewed remediation/capacity acceptance. Missing content/history/grant/audit/security schema, malformed policy, unsafe IDs, ignored writes and tested state/receipt rewrites fail closed. Guarded failures use `service_mutation_unavailable`, 503/no-store, and attempt coarse incomplete health evidence without content values.

No mutation replay, compensation or credit reservation is added to this update family. A lost acknowledgment may follow a complete page/history/tag/receipt commit; no hooks are started on that uncertain return. An identical later request is not a durable operation-ID retry. `if_lect` preserves its narrow optimistic-precondition contract; general lookup, retry and reconciliation remain R5.

No schema migration, production mutation, push, deployment or compliance sign-off occurs. Regulated business writes remain blocked. Four packages R3–R6 remain open, provisionally **18–32 engineering person-days** plus external acceptance; see the [scope register](w4b-remaining-scope-2026-11-02.md). The subsequent [creation slice](plugin-page-create-mutation-evidence.md) covers single/batch POST creation and its guarded reservation boundary. Next R3 slices are duplication, deletion/children and tag provisioning. Ingestion, other services/billing/jobs, external effects and global/deployed acceptance remain.
